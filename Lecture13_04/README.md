# Last Gate

세 차선으로 밀려오는 적을 막아 세 웨이브를 버티는 턴제 방어 게임이다.
Visual Studio에서 Lecture13_04를 시작 프로젝트로 지정한다. main.c 하나와 표준 C17만 필요하다.

| 명령 + Enter | 행동 |
|---|---|
| A / D | 위 / 아래 차선으로 포탑 이동 |
| F | 현재 차선으로 발사 |
| B | 모든 차선의 현재 적에게 폭탄 피해 |
| . | 한 턴 기다리기 |
| H / Q | 도움말 / 종료 |
| R | 승패 화면에서 재도전 |

`@`는 포탑, `>`는 탄환, `E`는 일반 적, `H`는 두 번 맞혀야 하는 장갑 적이다.
적이 왼쪽 끝에 닿으면 기지 HP가 줄어든다. 탄환은 한 턴에 두 칸, 적은 두 턴에 한 칸 움직인다.
차선을 옮기는 동안 다른 차선의 탄환도 계속 날아간다. 폭탄은 적이 모였을 때 쓰는 것이 유리하다.
웨이브를 끝내면 점수와 폭탄 하나를 받는다. 폭탄 보유 한도는 세 개이다.
도움말·잘못된 입력을 제외한 모든 행동은 턴을 소비한다.

## 강의에서 덧붙이는 순서

1. 포탑 이동과 ASCII 세 차선을 만든다.
2. Spawn으로 탄환과 적의 고정 배열 풀을 재사용한다.
3. UpdateBullets와 UpdateEnemies에 충돌과 기지 도달을 넣는다.
4. 직접 점수를 더하던 자리를 Emit(DESTROYED, ...)으로 바꾼다.
5. ApplyRules와 Record를 구독시켜 한 사건이 점수와 전투 기록에 함께 반영되게 한다.
6. Dispatch 뒤에 웨이브 종료와 게임 승패를 판정한다.

## 꼭 비교할 부분

- `Hit`는 즉시 적을 비활성화한다. 점수는 `Dispatch`에서 나중에 바뀐다.
- `Event`에는 풀 객체 주소 대신 종류·차선·수치를 복사한다.
- 탄환이 빠르면 도착 칸만 검사해서는 적을 건너뛴다. 이동 구간의 가장 가까운 적을 찾는다.
- 적 이동 후 겹침도 검사한다. 총알만 충돌 검사를 하면 서로 통과할 수 있다.
- 모든 피해를 반영한 뒤 승패를 결정한다. 마지막 적이 기지를 파괴하면 패배가 우선이다.
- 콜백은 규칙/기록만 처리하며, 큐 처리 중 새 사건 발행·구독 변경·풀 변경을 하지 않는다.

## 확장 과제

전투 기록 구독을 제거해도 게임 규칙이 유지되는지 확인한다.
파일 기록 구독자를 추가하거나, 다음 턴 큐를 만들어 분열하는 적의 생성 요청을 처리한다.
고정 난수 시작값을 바꾸어 새 배치를 만들되 테스트에서는 같은 값을 유지하여 재현한다.

## 검증

개발자 명령 프롬프트에서 `cl /std:c17 /utf-8 /W4 tests.c /Fe:tests.exe`로 별도 테스트를 빌드한다.
`tests.exe route.txt`는 세 웨이브 클리어 명령을 저장한다.
`Lecture13_04.exe < route.txt`로 플레이 경로를 재현할 수 있다.
tests.c는 게임 프로젝트에 포함하지 않는다.
