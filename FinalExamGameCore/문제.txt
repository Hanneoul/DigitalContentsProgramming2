최종 평가: 동시 턴 Dungeon Escape AI
===================================

[과제]
조별로 player0.c~player5.c 중 배정된 파일의 playerN_choose_command 함수 하나만
수정한다. 최신 상태 파일을 읽고 상하좌우 이동/공격/집기/버리기 중 한 Command를
반환한다. 다른 조의 소스, 코어, 헤더, 맵 또는 다른 조의 상태 파일을 참조/수정하지 않는다.
상세한 게임 판정은 Rule.txt를 기준으로 한다. 제출물은 자신의 .c 한 파일이다.

[예제]
현재 예제는 인접 열쇠를 집고, 인접 상대를 공격하고, 나머지는 방향을 순환하며
움직이는 단순 코드이다. 최단 경로 탐색이나 상대 행동 예측은 구현되어 있지 않다.
루프, 배열, 조건문, 파일 I/O를 읽고 자기 전략으로 개선한다.
H0는 학생 P0와 별개의 직접 조작용 추가 플레이어0이며 별도의 H0 시작점을 가진다.
wsad 이동, tgfh 공격, ikjl 집기/버리기, ESC 종료. Enter 없이 입력한다.

[좌표와 턴]
x는 논리 열, y는 행이다. 한 칸은 화면상 문자 두 개이며 배열은 terrain[y][x]다.
모든 NPC는 같은 턴 시작 상태를 받는다. 다른 NPC가 먼저 호출되어도 이동 결과는
반영되지 않는다. 전원의 명령을 모아 한 번에 판정한다. 공격은 턴 시작 위치에서
이동 후 상대 위치를 때린다. 충돌/공격 피해의 합은 턴당 최대 1이다.

[공개 API]
player_api.h에 Command, Position, PlayerState, Snapshot이 선언되어 있다.
파일을 직접 fopen(state_path,"r")한 뒤 snapshot_read(file,&state)로 읽을 수 있다.
snapshot_read는 코어 상태에 접근하지 않는 텍스트 파일 파서이며 파일을 닫지 않는다.
성공/실패와 무관하게 자신의 함수에서 fclose한다. 원하면 직접 파싱해도 된다.
Command 숫자: 이동 0~3, 공격 4~7, 집기 8~11, 버리기 12~15.
각 그룹의 순서는 상/하/좌/우. 무효 명령은 취소되고 피해를 받는다.

[상태 파일 v2]
FGC_STATE 2
size turn self key_owner key_x key_y key_start_x key_start_y exit_x exit_y
0 x y spawn_x spawn_y hp deaths rest
1 x y spawn_x spawn_y hp deaths rest
2 x y spawn_x spawn_y hp deaths rest
3 x y spawn_x spawn_y hp deaths rest
4 x y spawn_x spawn_y hp deaths rest
5 x y spawn_x spawn_y hp deaths rest
6 x y spawn_x spawn_y hp deaths rest
이어서 size줄의 지도: 각 줄은 정확히 size*2글자.

self는 P0~P5가 0~5, H0가 6이다. 총 PLAYER_COUNT=7, 학생 NPC_COUNT=6이다.
key_owner=-1이면 바닥 열쇠이며 key_x/key_y가 현재 위치이다.
소유자가 있으면 key_x/key_y는 마지막 바닥 위치이므로 소유자의 좌표를 확인한다.
key_start는 출구에서 소유자가 죽었을 때 열쇠가 돌아갈 최초 위치다.
hp=0이면 사망/휴식 중이다. deaths는 누적 사망 횟수, rest는 남은 휴식 수(uint64_t)다.
파일 지도에는 플레이어를 그리지 않는다. 위의 7개 기록으로 점유 상태를 판단한다.
지도는 ##, 두 칸 공백, (), 미획득 @-로 구성된다.
스냅샷은 모든 AI 호출 전에 저장하고, 실행별 폴더에 조별 최신 파일을 덮어쓴다.
원래 맵 dungeonmap.dat는 스냅샷과 다르며 AI의 입력으로 사용하면 안 된다.

[자원 관리 평가]
malloc/calloc/realloc 결과를 검사하고 모든 경로에서 free한다.
fopen/fopen_s 결과를 검사하고 모든 반환 경로에서 fclose한다.
player_api.h가 포함하는 diagnostics.h는 Debug에서 MS CRT _malloc_dbg 등의
할당 파일/줄 번호를 기록한다. 함수 반환 후 _CrtCheckMemory/_CrtDumpMemoryLeaks를
실행한다. FILE은 별도 추적기로 fclose 누락과 이중 닫기를 검출한다.
정상 AI의 playerN_diagnostics.log는 비어 있어야 한다. 메모리 추적은 Debug에서,
파일 추적은 Debug/Release에서 동작한다. 추적 매크로를 우회하지 않는다.
exit/abort/강제 종료나 시간 초과에서는 함수 반환 후 누수 검사가 실행되지 못한다.
그 경우 코어는 비정상 종료/시간 초과를 기록한다. 모든 오류의 줄 번호를 보장하지 않는다.

[강사 빌드/검증]
Visual Studio에서 FinalExamGameCore를 시작 프로젝트로 지정한다.
main은 main.c이며 전체 소스는 C17(/TC)이다. Debug/Release, x64/Win32를 지원한다.
실행 파일과 복사된 맵은 프로젝트 내부 bin\플랫폼\구성에 생성된다.
기본 맵은 실행 파일 옆에서 읽고 --map 상대 경로는 작업 폴더 기준이다.
verify.ps1은 네 가지 빌드, 동시 충돌/공격/사망/리스폰/아이템/출구/파일 판정,
자동 실행과 직접 조작 입력, 의도적 누수/시간 초과/크래시를 검사한다.
오류 주입은 verification 폴더의 별도 복사본에서 하며 제출 코드는 변경하지 않는다.

[배포]
학생에게 자기 playerN.c, player_api.h, diagnostics.h, 문제.txt, Rule.txt,
연습용 상태 파일만 별도 폴더로 배포한다. 강사가 제출 파일을 통합 빌드한다.
파일 파서를 직접 시험할 환경을 제공할 경우 snapshot.c/game.h는 읽기 전용으로
제공하거나 강사가 빌드한 라이브러리/실행 환경을 제공한다.
다른 조의 코드를 보지 못하게 하려면 전체 강사용 저장소를 배포하면 안 된다.
C 파일 분리나 별도 프로세스만으로 파일 열람 권한까지 막을 수 없다.
Windows ANSI API 기반 경로를 사용하므로 시스템 코드 페이지로 표현 가능한
짧은 경로를 권장한다. 상세 운영 규칙은 Rule.txt를 확인한다.
