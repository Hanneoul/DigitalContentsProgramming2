FinalExam01 게임 규칙 및 사용법
=============================

1. 시작 / 실행
P0~P5 여섯 NPC가 동시에 명령을 수행하는 자동 경기다. 직접 조작 캐릭터는 없다.
시작 화면에서 s/S를 누르면 진행하며, 다른 키는 무시하고 EOF는 시작을 취소한다.
  FinalExam01.exe
  FinalExam01.exe --auto --fast --plain --max-turns 100
  FinalExam01.exe --map "map.dat"
  FinalExam01.exe --self-test
  FinalExam01.exe --feature-test
--auto는 시작 입력, --fast는 프레임 대기, --plain은 ANSI 색상을 생략한다.
--max-turns는 1~10000의 수동 중단 한도다. 미지정 시 경기 종료 규칙까지 진행한다.
--max-rounds는 기존 명령과의 호환 별칭이다. Ctrl+C로 프로세스를 중단할 수 있다.

2. 맵과 좌표
좌표 (x,y)는 0부터 시작한다. x는 논리 열, y는 행이며 배열은 terrain[y][x]이다.
한 칸은 화면상 두 문자다. 맵은 3~32 크기의 n*n이며 한 줄은 정확히 2*n ASCII 문자다.
## 벽 / 두 칸 공백 바닥 / P0~P5 시작·리스폰 자리 / @- 열쇠 / () 출구.
시작점은 각각 하나, 열쇠와 출구는 하나씩 필요하다. P6~P9는 바닥으로 읽는다.
UTF-8 BOM, LF/CRLF, 마지막 행 개행 생략을 지원한다. 탭과 행 끝 공백 삭제는 금지한다.
잠긴 출구를 지나지 않고 모든 시작점에서 열쇠로 접근 가능해야 한다.
기본 dungeonmap.dat는 실행 파일 옆에서 읽고 빌드 때 자동 복사한다.
--map의 상대 경로는 실행 작업 폴더를 기준으로 한다.
현재 맵은 17x17, 열쇠 (8,4), 출구 (8,11)이다. 넓은 외곽과 문 근처의 짧은 벽·기둥으로
가까이 모여 싸우되 여러 방향에서 접근하도록 구성했다.
이전 13x13 맵은 dungeonmap_13x13.dat에 비교/연습용으로 보관한다.

3. 동시 턴 판정
리스폰 -> 동일한 시작 상태를 여섯 파일에 저장 -> 모든 생존 NPC 명령 수집 ->
유효성/충돌 판정 -> 이동/집기/버리기 -> 공격 -> 피해/사망 -> 탈출 순위 -> 열쇠 타이머 순이다.
AI 호출은 차례로 실행되지만 전원 수집 전에는 게임 상태를 변경하지 않는다.
다른 플레이어의 이번 명령은 공개하지 않는다. 같은 턴에 죽는 공격자도 공격은 수행한다.

4. 명령 / 충돌
모든 그룹은 상·하·좌·우 순서다.
  이동 COMMAND_UP/DOWN/LEFT/RIGHT = 0~3
  공격 COMMAND_ATTACK_UP/DOWN/LEFT/RIGHT = 4~7
  집기 COMMAND_PICK_UP/DOWN/LEFT/RIGHT = 8~11
  버리기 COMMAND_DROP_UP/DOWN/LEFT/RIGHT = 12~15
대기 명령은 없다. 열쇠를 들지 않았으면 빈 곳을 향한 공격으로 제자리에 설 수 있다.
이동은 한 칸이다. 벽/필드 밖/열쇠 없이 출구 진입/무효 명령은 취소되고 피해 1을 받는다.
같은 목적지로의 여러 이동, 이동과 버리기의 목적지 중복은 해당 명령을 모두 취소한다.
움직이지 않는 생존자의 칸으로 이동/버리기하면 행동한 쪽만 취소 피해를 받는다.
성공적으로 비우는 칸으로 이동하거나 버릴 수 있으며 자리 교환과 이동 사슬은 허용한다.
앞의 이동이 취소되면 뒤따르는 명령도 연쇄 취소한다. 플레이어 번호에 따른 우선권은 없다.
시체/탈출자는 자리를 점유하지 않는다. 바닥 열쇠 위에 서도 자동 획득하지 않는다.

5. 아이템 / 출구
집기는 인접 한 칸의 바닥 열쇠에만 가능하다. 같은 열쇠를 동시에 집으려 하면 모두 취소된다.
자기 발밑 집기는 없다. 타인의 소유 열쇠나 이번 턴 새로 떨어질 열쇠를 미리 집을 수 없다.
버리기는 소유자가 인접 바닥으로 한다. 벽/필드 밖/출구/다른 생존자의 최종 자리에는 못 버린다.
열쇠 소유자만 출구에 들어갈 수 있다. 그 턴 공격을 견디고 살아 있으면 탈출 순위를 얻는다.
열쇠 소유자가 공격하면 공격 취소와 HP 1 페널티를 받는다. 소유 여부는 턴 시작 기준이다.
소유자가 죽으면 최종 위치에 열쇠가 떨어진다. 출구에서 죽거나 탈출하면 최초 자리로 돌아간다.
사망을 먼저 판정하므로 출구 도착과 사망이 같은 턴이면 탈출 실패다.
누구도 소유하지 않은 채 완전한 30턴이 지나면 열쇠는 최초 위치로 돌아간다.
복귀/최초 생성 후 카운트는 30부터이며 소유 중은 정지·초기화한다.
드롭/사망/탈출로 새로 놓인 턴은 세지 않는다. 다음 완료 턴부터 29,28,... 순서로 감소한다.
30번째 턴에 집었다면 획득이 우선이다. 이미 최초 위치에 있어도 주기를 다시 시작한다.

6. 공격 / 사망 / 리스폰
HP 최대 2, 최초 및 부활 시 HP 2다. 상 공격은 (x-1,y-1),(x,y-1),(x+1,y-1) 세 칸이며
다른 방향도 같은 모양으로 회전한다. 공격자의 턴 시작 위치에서 상대의 이동 후 위치를 친다.
필드 밖/벽 칸은 제외하며 별도의 모서리 차폐는 없다. 여러 공격과 취소가 겹쳐도 피해는 턴당 1이다.
HP 0이면 사망한다. d번째 사망의 휴식은 2^(d-1)턴, 즉 1,2,4,8,...이다.
예: 10턴에 처음 죽으면 11턴은 쉬고 12턴 명령 수집 전에 부활한다.
자기 시작점이 점유되면 비워질 때까지 추가 대기한다. 그 대기로 피해/사망 수가 늘지 않는다.
생존 여부는 hp>0으로 판단하며 죽은 동안 AI를 호출하지 않는다.
휴식은 64비트로 저장하고 표현 범위를 넘으면 UINT64_MAX로 포화한다.

7. 화면 / 프레임
이전 화면 출력 시작부터 다음 출력까지 기본 500ms를 목표로 한다.
이전 출력·파일 처리·전체 AI 연산·판정 후, 다음 printf 직전에 max(0,500-경과ms)만 Sleep한다.
500ms를 넘겼으면 추가 대기가 없으며 실제 출력 시각을 다음 기준으로 삼는다.
공격과 피격은 같은 턴 프레임에 그린다. 별도의 공격 타이머나 즉시 중복 redraw는 없다.
Windows 스케줄링과 긴 연산 때문에 실제 간격이 더 길 수 있다.
HP 2는 밝은 고유색, HP 1은 어두운 고유색이다. 열쇠는 HP에 따른 밝은/일반 노랑 배경이다.
공격 범위는 노랑/**, 피격은 빨간 배경, 해당 턴 사망은 !!로 표시한다.
이름은 한글/영문 화면 칸 기준 16칸으로 정렬하고 HP는 [#][#] 사각 칸으로 표시한다.
R은 남은 휴식 비율에 따른 13칸 게이지, 옆 숫자T는 정확한 남은 턴이다.
컬러는 청록 배경 밑줄, plain에서는 =가 남은 부분이고 _가 빈 부분이다.
0T인 사망자는 이번 턴을 마친 뒤 부활 예정이거나 시작점 점유 대기이므로 [부활 대기]라고 표시한다.
D는 사망 횟수, 괄호는 좌표, C는 직전 명령이다. 숫자 열은 모든 행이 같은 폭을 사용한다.
맵의 문자 폭+순위표 48칸이 창 너비를 넘으면 순위표를 아래로 옮긴다. 리디렉션 기준 너비는 80칸이다.
맨 아래 KEY 줄은 바닥 좌표/복귀 남은 턴 또는 소유자/타이머 정지를 표시한다.

8. 순위 / 종료
탈출 순서대로 1~5위를 기록하고 탈출자를 플레이·공격·충돌·AI·리스폰에서 제외한다.
탈출마다 열쇠가 최초 자리로 재생성되고 문은 다시 잠긴다. 마지막 1명은 6위이며 경기 종료다.
1000턴까지 아무도 탈출하지 못하면 전원 공동 무승부다. 한 명이라도 탈출했다면 이 제한은 적용하지 않는다.
최종 순위는 실행 파일 폴더의 빈 rank00.txt~rank99.txt에 저장하고 기존 파일은 덮어쓰지 않는다.
100개가 모두 있으면 저장하지 않는다. --max-turns 조기 중단은 미확정 순위를 저장하지 않는다.

9. 학생 코드 / 상태 파일
학생은 자신의 playerN.c 함수와 playerN_name 문자열을 수정한다.
기본형은 fopen -> snapshot_read -> fclose 후 (state.turn+state.self)%4 이동만 한다.
벽 회피, 전투, 열쇠, 경로 탐색은 학생이 작성한다. 기본형 자체가 승리를 보장하지 않는다.
이름은 UTF-8 최대 63바이트이며 표시 폭을 넘으면 잘라 보여준다. 제어문자는 제거하고
한글/영문/CJK 외 특수 기호는 화면 폭 차이를 피하기 위해 ?로 표시할 수 있다.
상태 파일:
  FGC_STATE 3
  size turn self key_owner key_x key_y key_start_x key_start_y exit_x exit_y
  id x y spawn_x spawn_y hp deaths rest rank  (플레이어별 6줄)
  두 문자 단위 지도 size줄
  KEY_STATUS 남은턴
rank=0이면 경기 중(사망/휴식 포함), 1~6이면 순위 확정이다. key_owner=-1이면 바닥이다.
소유 중 key 좌표는 마지막 바닥 위치이므로 현재 소유자의 좌표를 확인한다.
Snapshot.key_respawn_remaining은 소유 중 0, 미소유 1~30이다.
파서는 연습 파일 호환을 위해 v2(rank 없음)와 KEY_STATUS 없는 파일도 읽는다.
타이머 확장이 없으면 미소유 30/소유 0을 기본값으로 쓴다.

10. 진단 / 검증 / 배포
AI는 매 턴 별도 프로세스이므로 전역/static 값은 다음 턴에 유지되지 않는다.
코어 메모리 포인터를 넘기지 않으며 시작 준비에 최대 10초, 준비 후 AI 실행에 1.5초를 허용한다.
비정상 종료/시간 초과는 무효 명령으로 처리한다. 프로세스 분리는 파일 접근 보안 샌드박스가 아니다.
다른 조 소스는 배포하지 않으며 강한 접근 차단은 OS 계정/ACL/VM을 사용한다.
Debug에서는 MS CRT 메모리 누수를, Debug/Release 모두 fopen/fopen_s/fclose 누락과 이중 닫기를 추적한다.
조별 로그는 run-실행ID-시각/playerN_diagnostics.log에 파일명과 줄 번호로 나온다.
다른 파일 API나 추적 매크로 우회, 강제 종료 이후 미실행 누수 검사까지 보장하지는 않는다.
--self-test는 게임 규칙·맵·순위·전원 worker 계약 및 신규 기능을 검사한다.
--feature-test는 타이머·이름·색상·게이지·스냅샷 호환 검사를 따로 실행한다.
특정 학생 AI가 열쇠를 줍거나 공격하도록 강제하는 옛 전략별 테스트는 제거했다.
변경 이력은 Build.txt, 오류 원인과 검증 기록은 BuildLog.txt, 개발 요구사항은 Exam.md를 참고한다.

공격 충전 규칙 추가 (FinalExam02)
- HP는 빨간 2칸과 현재/최대 숫자로, ATK는 초록 3칸과 현재/최대 숫자로 표시한다.
- 시작 및 리스폰 시 attack_charge=3. 허용된 공격은 명중 여부와 무관하게 1을 소모한다.
- 이동·집기·버리기 명령은 성공/취소 여부와 관계없이 1을 충전하며 최대 3이다.
- 충전 0에서 공격 시 공격이 취소되고 기존 취소 피해 1을 받는다. 허용되지 않은 공격 시도는 충전되지 않는다.
- 열쇠 소지 중 공격 금지는 유지하며 이때 공격 충전을 추가 소모하지 않는다.
- 사망/탈출/최하위 확정 시 공격 충전은 0이며 사망·휴식·탈출 중에는 충전하지 않는다.
- AI는 state.players[state.self].attack_charge를 읽어 남은 공격 횟수를 확인할 수 있다.
- v3 상태 파일 지도 뒤에 ATTACK_STATUS P0값 P1값 ... P5값을 추가했다.
  이 확장이 없는 구형 스냅샷은 충전 3으로 읽는다. v2/v3 및 KEY_STATUS 읽기 호환은 유지한다.
