# Callback Dungeon

보물 두 개와 열쇠를 모으고, 보스를 쓰러뜨린 뒤 출구로 탈출하는 턴제 던전이다.
Visual Studio에서 Lecture12_05를 시작 프로젝트로 지정하거나 이 폴더의 main.c만 C17로 컴파일한다.
외부 파일·자체 헤더·라이브러리·ANSI 설정이 필요 없다.

| 명령 + Enter | 행동 |
|---|---|
| W/A/S/D | 지도 이동 |
| F | 인접한 적 하나 공격 |
| 1 / 2 | 검 / 화염 장착 |
| P | 물약 사용: 체력과 마나 회복 |
| . | 기다리기 |
| H / Q | 도움말 / 종료 |
| R | 승패 화면에서 재도전 |

`@`는 플레이어, `g`는 추격자, `G`는 수문장, `B`는 보스이다.
`$`는 보물, `k`는 열쇠, `+`는 한 번만 쓸 수 있는 완전 회복 지점, `E`는 출구이다.
이동뿐 아니라 공격·장착·물약도 한 턴을 소비한다. 벽에 부딪히거나 허공을 공격해도 적이 움직인다.
도움말과 잘못된 명령에는 턴이 흐르지 않는다. 죽은 적은 반격하지 않는다.

## 직접 플레이할 때

가까운 고블린을 먼저 처리하고 왼쪽 보물과 아래쪽 열쇠를 찾는다.
화염은 강하지만 마나가 부족하면 검으로 바꿔야 한다. 적을 처치하면 마나를 일부 회복한다.
보스 전투 전에 회복 지점을 활용하고 장비를 미리 바꿔 두는 것이 유리하다.
두 적이 동시에 인접하면 배열에서 먼저 등록된 적을 공격한다. 위치 선택도 전투의 일부이다.

## 강의에서 덧붙이는 순서

1. Game과 지도 배열, Render, Move로 탐험만 만든다.
2. MonsterAt과 Sword를 넣어 고블린을 공격한다.
3. Hero.weapon에 함수 포인터를 저장하고 Fire로 교체한다.
4. Monster.think를 통해 같은 적 갱신 루프에 Chase와 Guard를 연결한다.
5. 보물·열쇠·회복·보스 처치와 탈출 조건을 붙인다.
6. 승패 뒤 Start로 상태 전체를 다시 초기화한다.

핵심 비교: `Attack`은 **누구를 공격할지**, 무기 콜백은 **어떻게 공격할지** 정한다.
함수 주소를 교체해도 대상 선택 코드를 고치지 않는다. 영문 화면은 인코딩 설정 의존성을 줄이기 위한 것이다.

## 작은 확장 과제

- 적 체력을 흡수하는 무기 콜백을 추가한다.
- 체력이 낮으면 도망가는 Think 콜백을 만든다.
- 같은 맵에서 적 목록·보상 배치만 바꾼 두 번째 스테이지를 추가한다.
- Chase를 BFS로 교체하고 단순 축 이동과 차이를 비교한다.

## 검증

개발자 명령 프롬프트에서 `cl /std:c17 /utf-8 /W4 tests.c /Fe:tests.exe`로 별도 테스트를 빌드한다.
`tests.exe route.txt`는 규칙 검증 후 클리어에 사용한 실제 명령을 저장한다.
`Lecture12_05.exe < route.txt`로 같은 승리를 재현할 수 있다.
tests.c는 게임 프로젝트의 컴파일 목록에 포함하지 않는다.
